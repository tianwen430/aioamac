# 新 AI 接手提示词

> 换了一个 AI、换了一个客户端、或者窗口断了要恢复——这里有三份可直接复制的 prompt。

---

## 场景 A：开一个新工位窗口

### 最简版（推荐）

**新建对话 → 把角色卡整份贴进去 → 末尾加一句：**

```
上班。
```

就这三步。角色卡本身已经是完整指令，不需要你补充解释。

### 如果 AI 反问你

它可能会问"我该做什么""路径在哪""要不要先看什么"。回这一句：

```
不要问，按角色卡执行。第一件事是启动自检，然后进入静默循环。
除总控外你不得输出任何文字，你的回复只能是工具调用。
```

### 如果它读不到文件

```
你的工作目录是 D:\ai-workflow。
先读 D:\ai-workflow\00_协议总纲.md 和 D:\ai-workflow\<你的角色卡>.md，
再执行启动自检。不要猜路径。
```

## 场景 B：换一台机器，从零重建

### 给新 AI 的总指令（整段复制）

```
你接手一套已经运行过的多 AI 协同工作流，需要在当前机器上完整复现它。

## 背景
这套系统用文件系统当消息队列：8 个独立 AI 窗口各占一个"工位"，
互相看不见对方对话，只通过往目录里写 Markdown 文件传递任务和成果。
人类只做两件事：往总控收件箱丢需求，看汇报终端的结果。

## 你手上的资源
套件目录（下称 KIT）包含：
- 00_从这里开始.md          入口，先读这个
- 02_协议总纲.md            唯一权威协议
- 01_操作手册\              5 份文档
- 02_角色卡\                8 张角色卡
- 03_工具\                  全部脚本，含 install.py 和 smoke_test.py
- 04_模板\                  指针、档案、22 种消息骨架

## 你的任务
按 00_从这里开始.md 的"30 分钟复制：五步"执行：
1. 确认 Python ≥ 3.10，装 mcp 和 watchdog
2. 跑 install.py --target <根目录> --project <项目名>
3. 合并 MCP 配置并提醒人类点「信任」
4. 跑 smoke_test.py，必须全绿
5. 按 01→02→04/05→03/06/08→07 顺序开 8 个窗口

## 硬要求
- 根目录必须纯 ASCII、无空格、不在同步盘。默认用 D:\ai-workflow
- 每步做完向我报告实际输出，不要只说"完成了"
- smoke_test.py 有红项就停下，按 04_故障排查.md 对应章节修，不要跳过
- 不要把 8 张角色卡的内容摘要后贴进窗口，必须整份贴

## 先做这一件事
读 KIT\00_从这里开始.md，然后用 5 行以内告诉我：
你打算把根目录设在哪、当前 Python 版本、下一步要执行哪条命令。
不要开始执行，等我确认。
```

### 它做完后你要检查的

| 检查项 | 怎么查 |
|---|---|
| 路径替换了 | 打开 `00_协议总纲.md` 搜 `{{ROOT}}`，应该搜不到 |
| 目录树完整 | `projects\P001_第一个项目\` 下有 9 个编号目录 |
| MCP 生效 | 新开对话问"列出 file-watcher 工具" |
| 冒烟全绿 | `smoke_test.py` 输出 `10 通过 / 0 失败` |
| 8 个心跳 | `开机检查.bat` 的"心跳"列都不是 `-` |

## 场景 C：窗口断了，恢复

### 循环被中断

```
继续静默循环。
从读 _ACTIVE_PROJECT.md 开始，按协议第 4 节走。不要输出文字。
```

### 窗口关了要重开

```
[贴角色卡全文]

继续。先读 D:\ai-workflow\projects\<项目名>\<你的工位>\_HEARTBEAT.md
看上一轮做到哪，再检查收件箱有没有未归档的文件。
不要重复处理已归档的文件。
```

### 上下文快满了，主动重启

```
处理完当前文件后停下，不要取新件。
我会关掉这个窗口重开。
```

然后关掉，重新贴角色卡 + `上班。`

**不会丢任务**——所有状态都在磁盘上。

## 场景 D：让 AI 帮你改这套系统

改之前必须让它先读协议：

```
你要修改这套协同工作流。先读 D:\ai-workflow\00_协议总纲.md 全文，
特别是第 3 节路由表和第 5 节硬约束。

改任何东西之前，先回答三个问题：
1. 这个改动会不会让某个前缀的落点变了？变了的话，谁去取？
2. 会不会让某个角色的职责边界变模糊？
3. 出问题怎么回滚？

回答完再动手。不要一次改多处。
```

### 加新工位的五处改动（最容易漏后两处）

1. `new_project.py` 的 `TREE` 和 `READY_DIRS`
2. 新角色卡 `09_xxx.md`
3. `00_协议总纲.md` 第 3 节路由表
4. `tools\status.py` 的 `STATIONS` ← 漏了状态面板看不见它
5. `tools\tidy.py` 的 `STATIONS` ← 漏了它的 `已处理` 不会归档

## 附：8 个工位的一句话职责（给人类速查）

| 工位 | 一句话 | 用什么模型 |
|---|---|---|
| 01 总控 | 唯一人类接口，出策划、分配版本、最终裁决 | 强模型（要做判断） |
| 02 实施布置 | 把策划切成可验收的任务单，核准成果 | 强模型 |
| 03 高级代码 | 判断问题是技术实现还是策划冲突，只出决策不写码 | 中等 |
| 04 代码员工 | 按任务单写代码 | 强模型（要写对） |
| 05 Debug | 按验收标准跑测试，能自己修就修 | 中等 |
| 06 美工 | 出图 + 写效果说明 + 通知接入 | 看需求 |
| 07 部署 | 只部署总控放行的版本，回执 | 小模型够用 |
| 08 智囊 | 独立审校策划稿，只挑错不给方案 | 与总控不同模型 |

**为什么智囊要用不同模型**：它和总控同模型会"顺着说"，挑不出真问题。
这是刻意设计，不是配置失误。

## 附：AI 常见误解与纠正

| AI 会说 | 纠正 |
|---|---|
| "我先看一下目录结构" | 禁止扫目录。只读任务单指定的文件 |
| "我已经完成了，总结如下" | 不许总结。你的回复只能是工具调用 |
| "我建议把架构改成…" | 你只做你工位的事，越权写 `[请示]_` |
| "这个验收标准有点模糊，我按理解实现了" | 不许猜。写 `[架构升级]_` 要求补规格 |
| "我顺手优化了一下旁边的代码" | 不许顺手重构。看到问题写 `[问题]_` |
| "两个方案都可以，看你们" | 高级代码必须给唯一结论 |
| "我处理完了，等下一个" | 归档后立刻回循环，不许停 |
