# 日常使用说明（人类视角）

> 你只需要记住两件事：
> **往 `01_总控\收件箱` 丢需求，看 `00_人类总控\汇报终端` 的结果。**
> 中间全是 AI 在转。

---

## 一、每天怎么用

### 早上的例行（1 分钟）

1. 双击 `开机检查.bat`
2. 看有没有 `⚠️ 卡住`
3. 看 `汇报终端` 有没有新的 `[待人类决策]`

### 白天的例行（看心情）

只看一个目录：

```
D:\ai-workflow\projects\<当前项目>\00_人类总控\汇报终端\
```

里面会出现这几类文件：

| 文件 | 含义 | 你要做什么 |
|---|---|---|
| `就绪_XX.md` | 某工位起来了 | 不用管 |
| `进度_XX.md` | 进度播报 | 扫一眼 |
| `[待人类决策]_XX.md` | **需要你拍板** | 看，然后回复 |
| `系统状态.md` | 谁上班谁下班 | 不用管 |
| `[阻塞]_vX.md` | 部署卡住 | 看，可能要联系平台方 |
| `上线_vX.md` | 上线成功 | 验收 |

**只有 `[待人类决策]` 和 `[阻塞]` 需要你动。**

## 二、怎么下需求

### 方法 1：直接跟总控窗口说

在总控窗口里说：

```
新需求：给拍卖行加一个"一键出价"按钮，最高加价 3 次，超过就提示。
```

总控会自己写 `[需求]_` 文件并走流程。

### 方法 2：自己写文件（更可控）

在 `01_总控\收件箱\` 新建 `[需求]_20260101-0900-01.md`，用这个骨架：

```markdown
# [需求] 一键出价按钮

- 需求编号：REQ-20260101-01
- 提出：人类
- 优先级：P1
- 代码基线：V1.0.0 / schema v9 / 84 测试全绿

## 一、背景
现在每次出价都要手动点 + 输入金额，重复操作烦。

## 二、目标
拍卖行界面加一个"一键出价"按钮，自动按最小加价幅度出价。

## 三、范围（必须实现）
1. 按钮位置：出价区右侧
2. 每次点击 = 当前价 + 最小加价幅度
3. 最多连点 3 次，第 4 次提示"今日次数已用完"
4. 次数每日 00:00 重置

## 四、明确不做
- 不做批量出价
- 不做自动跟价

## 五、验收标准
1. 点击后价格 = 当前价 + 配置的最小加价幅度
2. 连点 3 次后第 4 次被拒，价格不变
3. 跨日后次数恢复为 3
4. 余额不足时按钮置灰

## 六、约束
- 不新增依赖
- 不改存档 schema
```

### 写需求的三条经验

1. **验收标准必须能判真假。** "体验流畅"不合格；"点击后 100ms 内价格更新"合格。
2. **写清楚"不做什么"。** 不写，AI 会顺手加东西。
3. **给基线。** 告诉它现在的版本、测试数、代码在哪，它就不用猜。

## 三、怎么回 `[待人类决策]`

总控会写一个文件，形如：

```markdown
# [待人类决策] 20260101-0930-01

## 分歧
智囊认为 §3.2 的"最多 3 次"和 §5 的"每日重置"矛盾，因为没写清楚是
"每日 3 次"还是"总共 3 次"。

## 我的判断
我倾向"每日 3 次"，理由是需求原文说"每日 00:00 重置"。

## 需要你定
A. 每日 3 次
B. 总共 3 次（不可恢复）
```

**直接在总控窗口里回 A 或 B**，或者编辑这个文件在末尾加一行：

```
人类裁决：A
```

总控下一轮会读到。

## 四、暂停与恢复

### 暂停全部（要改代码、要重启机器）

双击 `暂停全部.bat`，或：

```bash
python D:\ai-workflow\tools\pause.py on
```

**注意**：正在处理的文件不会中断，员工会在**下一轮循环开头**停下。
停下后窗口会保持静默，不再轮询。

### 恢复

```bash
python D:\ai-workflow\tools\pause.py off
```

**然后必须逐个窗口发一句「继续监听」**——暂停后窗口不会自己醒，需要人叫。

顺序：01 → 02 → 04/05 → 03/06/08 → 07。

### 只暂停一个工位

没有这个功能。要么全停，要么让那个工位自己把活干完。
如果确实要停一个，关掉那个窗口就行。

## 五、切项目

编辑 `D:\ai-workflow\_ACTIVE_PROJECT.md`：

```markdown
project: P003_新项目
root: D:\ai-workflow\projects\P003_新项目
status: ACTIVE
```

**所有员工下一轮自动跟过去，不需要重启任何窗口。**

前提：`P003_新项目` 的目录树已经存在。不存在就先用 `new_project.py` 建。

---

## 六、新建项目

```bash
python D:\ai-workflow\tools\new_project.py P003_新项目
```

会做四件事：
1. 建全套目录树（`00_人类总控` + `01`~`08`）
2. 写 `_GLOBAL_STATUS.md`（ACTIVE）和 `_VERSION.md`（0）
3. 写 `_PROJECT.md` 骨架
4. 把指针切过去

然后编辑 `_PROJECT.md` 填 `code_root`、`deploy_target`、`baseline`。

**注意**：切项目后，旧项目的窗口会自动去新项目。想同时跑两个项目，需要开两组窗口（不建议）。

## 七、看状态

```bash
python D:\ai-workflow\tools\status.py
```

输出：

```
工位          积压  最后活动      心跳        状态
--------------------------------------------------
01-总控          2  3分钟前       12秒前      🔄 运行中
02-实施布置      0  8分钟前       45秒前      ✅ 空闲（正常）
03-高级代码      1  25分钟前      25分钟前    ⚠️ 卡住：积压 1 项，25 分钟无动作
```

**状态含义**：

| 状态 | 含义 | 要做什么 |
|---|---|---|
| ✅ 空闲（正常） | 没活，心跳正常 | 不用管 |
| 🔄 运行中 | 有积压，最近有动作 | 不用管 |
| ⚠️ 卡住 | 有积压但很久没动 | 去那个窗口看看 |
| ⚪ 未接过活 | 从没处理过文件 | 正常，或窗口没起来 |
| 💤 下班（待命） | 有 `_OFFDUTY.md` | 发「上班」 |

加 `--stale 15` 可以把"卡住"阈值改成 15 分钟。

## 八、定期瘦身（每周一次）

```bash
python D:\ai-workflow\tools\tidy.py            # 先预览
python D:\ai-workflow\tools\tidy.py --apply    # 再执行
```

做四件事，**不删任何文件**：

1. `已处理\` 里的文件按月份移入 `已处理\YYYY-MM\`
2. `汇报终端\进度_*.md` 移入 `_archive\`
3. `_READY.md` 超 50 行 → 前面的移入 `_archive\`
4. `_HEARTBEAT.md` 只留最近 5 行

**为什么不让员工自己做**：员工没有全局视野，删错一个文件不可逆。瘦身必须人来做。

## 九、加新项目 / 加新工位

### 加项目

`new_project.py` 就够了。项目之间完全隔离，共享同一批窗口。

### 加新工位（比如"运营"）

需要改五处，缺一不可：

1. **建目录**：在 `new_project.py` 的 `TREE` 里加 `09_运营\{收件箱,已处理}`，
   同步加 `READY_DIRS`。已有项目手动建。
2. **写角色卡**：`09_运营.md`，照现有卡的结构写（启动自检 + 监听路径 + 前缀路由 + 硬约束 + 静默纪律）。
3. **加前缀**：在 `00_协议总纲.md` 第 3 节路由表里加新前缀和落点。
4. **加状态检查**：在 `tools\status.py` 的 `STATIONS` 里加一行，否则 `status.py` 看不见它。
5. **加归档**：在 `tools\tidy.py` 的 `STATIONS` 里加一行，否则它的 `已处理` 不会按月归档。

**最容易漏的是 4 和 5**——新工位跑起来了，但状态面板看不见、目录无限膨胀。

## 十、什么时候该人工介入

| 情况 | 处置 |
|---|---|
| 同一工位连续两次报同一个阻塞 | 看那个工位的 `_HEARTBEAT.md`，可能是窗口挂了 |
| `[待人类决策]` 堆积 3 个以上 | 说明你在拖，先清掉 |
| 成果验收不过但 Debug 说通过 | 抽查 `05_Debug\测试报告\`，看验收标准有没有被改软 |
| 版本号跳号 | 查 `01_总控\已处理` 有没有重复的 `[汇报]_` |
| 部署回执来了又收到新的 `[发布]_` | 总控逻辑出错，检查它有没有把 `[部署回执]_` 当成 `[汇报]_` |

## 十一、成本控制

每个窗口都是一个持续运行的 AI 会话。8 个窗口 = 8 份持续消耗。

**省钱的三个做法**：

1. **不用的工位关掉。** 只做代码不做美术，就关掉美工窗口。链路会在需要它的时候卡住，
   你能立刻发现。
2. **晚上暂停。** `pause.py on` 之后窗口会停轮询，不再消耗。
3. **用便宜模型跑闲职工位。** 部署、智囊这类低频角色可以用小模型；
   总控和实施布置必须用强模型（它们做判断）。

**注意**：暂停后恢复需要人工逐个叫醒。如果只是过夜，暂停是值得的；
如果只是去吃个饭，别暂停。
