# 快速复制指南（详细版）

> 给要换机器、或要给第二个人搭一套的人。跟着做，不要跳步。
> 预估耗时：**首次 30 分钟**，熟练后 12 分钟。

---

## 0. 前置条件

| 项 | 要求 | 怎么查 |
|---|---|---|
| 操作系统 | Windows 10/11 | — |
| Python | 3.10 以上 | `python --version` |
| Python 包 | `mcp`、`watchdog` | `python -c "import mcp, watchdog"` |
| AI 客户端 | 支持 MCP + 多会话（如 WorkBuddy） | — |
| 磁盘 | ≥ 200MB 空闲 | — |

装包：

```bash
python -m pip install mcp watchdog
```

> 如果 `python` 不是命令，试 `py -3 --version`。把下面所有 `python` 换成 `py -3`。

---

## 1. 选根目录

```
D:\ai-workflow
```

三条硬要求：

1. **路径无空格、无中文。** `C:\Users\张三\我的文档\ai` 会出问题。
2. **不要放 OneDrive / 坚果云同步目录。** 同步进程会锁文件，导致监听抖动、文件半写。
3. **不要在 `C:\Program Files` 下。** 权限不足。

根目录里会放：协议总纲、8 张角色卡、`tools\`、`file_watcher_mcp.py`、`_ACTIVE_PROJECT.md`、`projects\`。

---

## 3. 注册 MCP

### 方式 A：自动（推荐）

```bash
python install.py --target D:\ai-workflow --write-mcp
```

会把 `file-watcher` 合并进 `~/.workbuddy-ai/mcp.json`，**保留你原有的其它 server**。
如果原文件无法解析，会自动备份成 `mcp.json.bak`。

### 方式 B：手动

打开 `C:\Users\<你>\.workbuddy-ai\mcp.json`，把 `_mcp_config.json` 里的
`mcpServers.file-watcher` 整块复制进去。注意 JSON 逗号。

### 然后必须做：点「信任」

**打开 WorkBuddy → 连接器管理 → 右上角「自定义连接器」→ 找到 `file-watcher` → 点「信任」。**

不点这一步，MCP 工具不会出现在工具列表里，所有员工会永远卡在 `NO_FILE`。
这是最高频的安装失败原因。

**检查点**：

- [ ] `mcp.json` 里 `file-watcher.command` 指向真实存在的 python.exe
- [ ] `args` 里的 `.py` 路径存在
- [ ] 客户端已对 `file-watcher` 点信任
- [ ] 新开一个对话，问 AI「列出你可用的 file-watcher 工具」，能答出 `wait_for_files` 和 `list_pending`

## 5. 开窗口

### 贴什么

每个窗口：新建对话 → 把对应角色卡**整份**贴进去（不是摘要，是全文）→ 发「上班」。

角色卡在 `D:\ai-workflow\` 根目录，文件名就是工位名。

### 顺序与理由

| 步 | 工位 | 理由 |
|---|---|---|
| 1 | `01_总控.md` | 只有它能建项目目录树。它没起来，其他窗口启动自检会失败 |
| 2 | `02_实施布置.md` | 依赖目录树 |
| 3 | `04_代码员工.md` | 主力生产者 |
| 4 | `05_Debug.md` | 接代码员工的产出 |
| 5 | `03_高级代码.md` | 按需介入 |
| 6 | `06_美工.md` | 按需介入 |
| 7 | `07_部署.md` | 平时闲，最后起 |
| 8 | `08_智囊.md` | 可选。不开则需求无审校 |

### 开完自检

双击 `开机检查.bat`：


## 6. 跑第一次真实需求

在 `01_总控\收件箱` 放一个文件：

`D:\ai-workflow\projects\P001_第一个项目\01_总控\收件箱\[需求]_20260101-0900-01.md`

内容用 `04_模板\消息模板_全前缀.md` 的第一节骨架。

然后盯 `00_人类总控\汇报终端\`，应该依次出现：

1. `进度_{ID}.md` — "已收需求，初稿已送审"
2. 几分钟后 `[待人类决策]_{ID}.md` 或直接进 `[策划]_`
3. 实施布置拆单后，`04_代码员工` 的 `已处理` 开始出现文件
4. `05_Debug\测试报告\` 出现报告
5. `01_总控\成果区\_待发布\` 出现成果
6. 有 `[汇报]_` 后，`07_部署\收件箱\[发布]_v1.md` 出现

**如果第 1 步就没动静**：总控窗口没在监听，或 MCP 没信任，或 `PAUSED`。

## 迁移已有项目（不是从零开始）

如果新机器上已经有一个代码仓库，想接进这套流水线：

1. 跑安装，但项目名用真实名字：
   ```bash
   python install.py --target D:\ai-workflow --project P002_我的项目
   ```

2. 编辑 `D:\ai-workflow\projects\P002_我的项目\_PROJECT.md`：
   ```yaml
   name: P002_我的项目
   title: 我的项目 V1
   code_root: D:\my-repo\src          ← 真实源码目录
   deploy_target: Cloudflare Pages    ← 真实部署目标
   baseline: D:\my-repo\docs\总纲.md   ← 需求与验收的权威依据
   ```

3. 把已有的需求/设计文档复制到 `D:\ai-workflow\projects\P002_我的项目\` 下。

4. **不要**把代码复制进 `projects\`——`code_root` 指向原位置，员工直接在原地作业。

5. 确认 `_ACTIVE_PROJECT.md` 的 `root` 指向 `P002_我的项目`。

**关键**：`code_root` 必须是绝对路径。写相对路径，代码员工会写到 `04_代码员工\代码产出\` 里，
和你的真实仓库脱节。

## 从旧机器搬过来（保留历史）

想连历史一起搬：

1. 旧机器：停所有窗口 → 双击 `暂停全部.bat`
2. 复制整个 `D:\ai-workflow` 到新机器同名路径（或新路径）
3. **如果路径变了**，必须改三处：
   - `_ACTIVE_PROJECT.md` 的 `root`
   - 每张角色卡里被替换过的绝对路径（`grep -r "旧路径" .` 找）
   - `_mcp_config.json` 和 `mcp.json` 里的 `file_watcher_mcp.py` 路径
4. 跑 `smoke_test.py` 验证
5. 新机器上重新点 MCP 信任

> 更省事的做法：路径保持一致（都用 `D:\ai-workflow`），就只需重新点信任。
