# 故障排查

> 按现象查，不要按原因猜。每条都给了"怎么确认"和"怎么修"。

---

## 快速诊断树

```
整套不动了
  ├─ 所有窗口都没反应？
  │    ├─ 开机检查.bat → 全局状态是 PAUSED？ → 是：pause.py off，逐个叫醒
  │    └─ 是 ACTIVE？ → 看单个窗口
  │
  ├─ 只有一个窗口不动？
  │    ├─ 那个窗口最后说了什么？
  │    │    ├─ 说了文字（总结/状态）→ 循环已断，发「继续静默循环」
  │    │    ├─ 报工具错误 → 看下面的 MCP 章节
  │    │    └─ 什么都没说，但心跳停了 → 窗口挂了，重开
  │    └─ status.py 显示 ⚠️ 卡住 → 积压多少？看对应收件箱
  │
  └─ 有文件在动，但卡在某一环？
       └─ 看 status.py 哪个工位积压 → 那个工位的窗口有问题
```

## 1. MCP 工具不可用（最高频）

### 现象

员工回复类似：

- "我没有 `wait_for_files` 这个工具"
- "找不到 mcp__file-watcher__wait_for_files"
- 一直 `NO_FILE` 但收件箱明明有文件

### 怎么确认

新开一个对话，问：「列出你可用的 file-watcher 工具」。

正常应答出 `wait_for_files` 和 `list_pending`。

### 怎么修

**逐项排查，从最可能开始：**

1. **没点「信任」**
   WorkBuddy → 连接器管理 → 右上角「自定义连接器」→ `file-watcher` → 点「信任」。
   **90% 的问题在这一步。**

2. **`mcp.json` 路径错**
   打开 `C:\Users\<你>\.workbuddy-ai\mcp.json`：
   ```json
   {
     "mcpServers": {
       "file-watcher": {
         "command": "C:\\Users\\80438\\.workbuddy-ai\\binaries\\python\\versions\\3.13.12\\python.exe",
         "args": ["-u", "D:\\ai-workflow\\file_watcher_mcp.py"],
         "env": { "PYTHONUTF8": "1", "PYTHONIOENCODING": "utf-8" }
       }
     }
   }
   ```
   检查：`command` 的 python.exe 真的存在吗？`args` 里的 .py 真的存在吗？
   路径里的反斜杠必须双写（`\\`）。

3. **缺依赖包**
   ```bash
   python -c "import mcp, watchdog; print('ok')"
   ```
   报错就 `python -m pip install mcp watchdog`。

4. **JSON 语法错**
   多一个逗号、少一个引号，整份配置会失效。
   ```bash
   python -c "import json;json.load(open(r'C:\Users\<你>\.workbuddy-ai\mcp.json',encoding='utf-8'));print('ok')"
   ```

### 降级方案（MCP 死活修不好时）

**所有员工都可以不用 MCP，改用 CLI 监听。** 在角色卡里把取件方式改成：

```bash
python D:\ai-workflow\tools\wait_files.py --timeout 480 "路径1" "路径2"
```

返回值语义完全一样（`BACKLOG:` / `NEW:` / `NO_FILE` / `ERROR:`）。

**代价**：每次取件是一个 Bash 调用，会阻塞 8 分钟。有些客户端对单次工具调用有超时上限
（比如 2 分钟），会被强制打断。

**缓解**：把 timeout 降到 90–110 秒，轮询频率提高。功能不变，只是醒得更勤。

> 这套系统最初就是这么跑的（`[请示]_监听降级_实施布置_20261031-1341.md` 记录过这次降级）。

## 2. 循环被"检测死循环"中断

### 现象

窗口突然停下，提示类似"检测到重复操作已中断"。

### 原因

平台把**连续多次参数完全相同的工具调用**判定为死循环。静默轮询天然会重复同一条命令。

### 怎么修

角色卡里已有防循环纪律，检查这三条是否真的在执行：

1. **每轮先写 `_HEARTBEAT.md`**（含时间戳，内容每轮不同）→ 把连续的 Bash 调用隔开
2. **`--timeout` 每轮取不同值**（450–540 之间），不许每轮都用 480
3. **每 5 轮插一次 `list_pending`**（参数不同）

### 已经断了怎么办

在那个窗口发一句：

```
继续静默循环
```

它会重新进入循环。历史任务不受影响，收件箱里的文件也不会丢。

## 3. 员工说了话，循环断了

### 现象

窗口输出了一段总结/状态/"已完成"，然后不动了。

### 原因

**AI 一输出文字，这一轮就结束了。** 这是所有基于对话的 AI 的固有行为，不是 bug。

### 怎么修

1. 发「继续静默循环」
2. 检查角色卡里「静默纪律」那节还在不在（有人精简角色卡时容易删掉）
3. 如果它反复说话，在角色卡最前面加一句：

```
**你现在处于静默模式。你的每一条回复都必须是工具调用，不得包含任何自然语言。**
```

## 4. 全局状态卡在 PAUSED

### 现象

所有窗口启动后立刻停，`_READY.md` 里出现 `PAUSED ack`。

### 怎么修

```bash
python D:\ai-workflow\tools\pause.py off
```

**然后逐个窗口发「继续监听」**——暂停后窗口不会自己醒。

顺序：01 → 02 → 04/05 → 03/06/08 → 07。

### 怎么确认

```bash
python D:\ai-workflow\tools\pause.py status
```

## 5. 锁残留，抢不到

### 现象

`lock.py acquire` 一直返回 `BUSY 900s` 之类的。

### 原因

窗口崩溃时没释放锁。锁 15 分钟后自动失效，但你可能等不了。

### 怎么修

```bash
python D:\ai-workflow\tools\lock.py status     # 看有哪些锁
python D:\ai-workflow\tools\lock.py clear      # 全清
```

**注意**：清锁前确认对应窗口真的没在干活。清了一个正在运行的窗口的锁，
会导致两个进程同时处理同一文件。

`开机检查.bat` 第一步就是清锁，所以每天早上双击它是个好习惯。

## 6. 中文乱码 / 编码错误

### 现象

- 批处理窗口里中文变成 `锟斤拷`
- Python 报 `UnicodeEncodeError`
- 写入的 md 文件打开是乱码

### 怎么修

1. **批处理**：第一行必须有 `chcp 65001 >nul`
2. **Python**：脚本末尾有
   ```python
   try:
       sys.stdout.reconfigure(encoding="utf-8")
   except Exception:
       pass
   ```
3. **MCP 环境变量**：
   ```json
   "env": { "PYTHONUTF8": "1", "PYTHONIOENCODING": "utf-8" }
   ```
4. **所有文件读写显式指定** `encoding="utf-8"`

### 根治

**把根目录放在纯 ASCII 路径下**（`D:\ai-workflow`）。
中文路径 + 空格 + 中文文件名，是编码问题的最大来源。

## 7. 同一文件被处理两次

### 现象

下游收到两份一模一样的产出，ID 相同。

### 原因（按可能性排序）

1. **同一角色开了两个窗口** ← 最常见
2. 清锁时清掉了正在运行的窗口的锁
3. 窗口崩溃后重启，但旧窗口还在后台

### 怎么修

1. 关掉多余窗口。**一个角色只能有一个窗口。**
2. 锁只能防"同时"，防不了"先后"。重复消费只能靠人保证单窗口。

### 已经重复了怎么办

1. 下游保留一份，另一份移到 `已处理\_duplicate\`
2. 检查版本号有没有被分配两次

## 8. 部署无限重复

### 现象

同一个版本被反复部署，`[部署回执]_v3.md` 出现很多次。

### 原因

**总控把 `[部署回执]_` 当成了 `[汇报]_`，又发了一次 `[发布]_`。**

### 怎么修

1. 立刻暂停：`pause.py on`
2. 检查总控的 `已处理\` 里有没有重复的 `[部署回执]_`
3. 检查 `07_部署\收件箱` 有没有多个同版本 `[发布]_`，删掉多余的
4. 确认总控角色卡里这条还在：
   > `[部署回执]_` → **只归档**，写 `上线_{版本}.md`。**禁止再写 `[发布]_`**
5. 恢复

## 9. 收件箱有文件，但没人取

### 排查顺序

1. **那个工位的窗口起来了吗？** 看 `_HEARTBEAT.md` 存在吗、时间新吗
2. **监听路径对吗？** 打开角色卡，核对 `listen` 里的路径和实际目录
3. **文件名前缀对吗？** 前缀错了会被当成未知类型，员工可能跳过
4. **文件是不是临时文件？** `.tmp` / `.part` / `~$` 开头会被忽略
5. **是不是 `PAUSED`？** 看 `_GLOBAL_STATUS.md`

### 手动验证监听

```bash
python D:\ai-workflow\tools\wait_files.py --timeout 5 "D:\ai-workflow\projects\P001_第一个项目\01_总控\收件箱"
```

有文件应该立刻返回 `BACKLOG: ...`。

## 10. 文件读到一半（半写）

### 现象

员工读到的 md 是截断的，或者 JSON 解析失败。

### 原因

写入方还在写，读取方已经开始读。

### 怎么修

`wait_for_files` 有 `settle_seconds`（默认 1.0），会等 1 秒再确认。
如果文件很大或磁盘慢，加大它：

```python
mcp__file-watcher__wait_for_files(paths, timeout_seconds=480, settle_seconds=2.5)
```

### 预防

**写文件用"先写临时名再改名"**：

```bash
# 先写 xxx.md.tmp，写完 mv 成 xxx.md
```

改名是原子操作，不会出现半写文件。

## 11. 目录越来越大

### 现象

`已处理\` 里有几千个文件，`汇报终端` 有几百个进度文件。

### 怎么修

```bash
python D:\ai-workflow\tools\tidy.py            # 预览
python D:\ai-workflow\tools\tidy.py --apply    # 执行
```

**不会删任何文件**，只按月归档、滚动台账、截断心跳。

### 注意

**不要让员工自己做瘦身。** 员工没有全局视野，删错一个文件不可逆。

## 12. 换了机器 / 改了根目录路径

### 现象

所有绝对路径失效，员工报"文件不存在"。

### 怎么修

1. 改 `_ACTIVE_PROJECT.md` 的 `root`
2. 全局搜旧路径：
   ```bash
   grep -rl "旧路径" D:\新路径\*.md
   ```
   逐个替换
3. 改 `_mcp_config.json` 和 `~/.workbuddy-ai/mcp.json`
4. 重新点 MCP「信任」
5. 跑 `smoke_test.py`

### 预防

**保持路径一致**（都用 `D:\ai-workflow`）。换机器时路径不变，就只需重新点信任。

## 13. 窗口上下文快满了

### 现象

员工开始忘事、重复读同一个文件、忽略角色卡里的规则。

### 原因

每个窗口是长会话，上下文会累积。8 分钟一轮 × 几小时 = 很多轮。

### 怎么修

1. **让它在干净的时候重启**：处理完当前文件、收件箱空的时候，关掉窗口重开，重新贴角色卡
2. **角色卡不要膨胀**：只写"我是谁、我听哪里、我怎么分流"，不要往里塞业务知识
3. **业务知识放文件**：`设计总纲.md`、`_PROJECT.md`，让员工按需读，而不是常驻上下文

### 什么时候该重启

- 连续运行超过 6 小时
- 开始出现"忘了归档""读错路径"这类低级错误
- 心跳正常但产出质量下降

**重启不会丢任务**——所有状态都在磁盘上。收件箱里没处理的文件会被新窗口接着取。

## 14. 快速自检脚本

不想一条条查，直接跑：

```bash
python D:\ai-workflow\tools\smoke_test.py
python D:\ai-workflow\tools\status.py --stale 15
python D:\ai-workflow\tools\pause.py status
python D:\ai-workflow\tools\lock.py status
```

四条命令覆盖 90% 的故障面。

## 附：故障处置速查表

| 现象 | 最可能原因 | 一条命令修好 |
|---|---|---|
| 全员不动 | PAUSED | `pause.py off` + 逐个叫醒 |
| 一个窗口不动 | 说了话 / 循环被拦 | 发「继续静默循环」 |
| 一直 NO_FILE | MCP 没信任 | 连接器管理点信任 |
| 抢不到锁 | 锁残留 | `lock.py clear` |
| 同一文件处理两次 | 开了两个窗口 | 关掉一个 |
| 部署重复 | 总控把回执当汇报 | 暂停 + 清多余 `[发布]_` |
| 中文乱码 | 缺 chcp / 编码参数 | 换纯 ASCII 路径 |
| 目录膨胀 | 没跑瘦身 | `tidy.py --apply` |
| 换机器全挂 | 绝对路径失效 | 改指针 + 全局替换 + 重信任 |
