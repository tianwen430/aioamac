# 从这里开始

> **给接手的人（或 AI）**：这份文档是整套工具的唯一入口。读完它，你就能在另一台机器上
> 30 分钟内复制出同样的多 AI 协同工作流。不要跳读，按顺序走。

---

## 这套东西是什么

一套**用文件系统当消息队列**的多 AI 协同流水线。8 个独立 AI 窗口各占一个"工位"，
互相看不见对方的对话，只通过往目录里写 Markdown 文件来传递任务和成果。

```
人类 → 总控 → 实施布置 → 高级代码 / 代码员工 / 美工 → Debug → 部署 → 人类
                ↑                                        ↓
                └──────────── 智囊审校（可选） ←──────────┘
```

**它解决的真问题**：单个 AI 会话做不了长周期项目——上下文会满、会跑偏、会忘。
拆成 8 个只干一件事的窗口，每个窗口的上下文都很短，而且互相能纠错。

**它的边界**：单机、单用户、文件系统级。不解决跨机器同步、多人类并发、冲突合并。

### 为什么是 8 个而不是 7 个

`01`–`07` 是**七个核心工位**，缺一不可，缺了链路就断：

```
总控 / 实施布置 / 高级代码 / 代码员工 / Debug / 美工 / 部署
```

`08_智囊` 是**可选的第 8 个**，只管策划审校，不参与生产。

- **开它**：需求会先经一轮独立审校，能挑出总控自己看不见的遗漏。成本是一个窗口。
- **不开它**：链路照样跑。总控遇到需求直接定稿（或标 `免审`），但就没人给它挑错了。

建议开。它是最便宜的质量保险——用不同模型，才不会顺着总控的话说。

## 30 分钟复制：五步

### 第 1 步：选一个控制层根目录（1 分钟）

建议路径短、无空格、无中文：

```
D:\ai-workflow          ← 推荐
C:\ai-workflow          ← 也可以
```

**不要**放在 `C:\Program Files`、OneDrive 同步目录、或带空格的路径下——批处理和
Python 脚本在中文+空格路径上容易出编码问题。

### 第 2 步：跑安装脚本（3 分钟）

把整个套件文件夹复制到新机器，然后：

```bash
cd 套件目录\03_工具
python install.py --target D:\ai-workflow --project P001_第一个项目
```

它会自动做六件事：
1. 建控制层根目录
2. 复制协议总纲 + 8 张角色卡，并把 `D:\AIOA\AI协同工作流_可复制套件\05_应用\test\smoke-wf-root` 替换成 `D:\ai-workflow`
3. 复制 `tools\` 和根目录批处理
4. 建第一个项目的完整目录树
5. 生成 MCP 配置片段
6. 打印剩余人工步骤

> 如果报"缺包"，先跑：`python -m pip install mcp watchdog`

### 第 3 步：注册文件监听 MCP（5 分钟）

安装脚本已生成 `D:\ai-workflow\_mcp_config.json`，内容形如：

```json
{
  "mcpServers": {
    "file-watcher": {
      "command": "C:\\...\\python.exe",
      "args": ["-u", "D:\\ai-workflow\\file_watcher_mcp.py"],
      "env": { "PYTHONUTF8": "1", "PYTHONIOENCODING": "utf-8" }
    }
  }
}
```

把这个 `file-watcher` 条目合并进 `~/.workbuddy-ai/mcp.json`（Windows 是
`C:\Users\<你>\.workbuddy-ai\mcp.json`）。或者安装时直接加 `--write-mcp` 让它自动合并。

然后：**打开 WorkBuddy → 连接器管理 → 右上角自定义连接器 → 对 `file-watcher` 点「信任」**。
不点信任，MCP 不会生效。

### 第 4 步：验证（2 分钟）

```bash
python D:\ai-workflow\tools\smoke_test.py
```

8 项全绿才继续。任何一项红，去 `01_操作手册\04_故障排查.md` 找对应项。

### 第 5 步：开 8 个窗口（15 分钟）

每个窗口新建一个对话，把对应角色卡的内容**整份贴进去**，然后发一句「上班」。

| 顺序 | 窗口 | 贴哪个文件 | 为什么这个顺序 |
|---|---|---|---|
| 1 | 总控 | `01_总控.md` | 只有它能建目录树，必须第一个起 |
| 2 | 实施布置 | `02_实施布置.md` | 依赖目录树存在 |
| 3 | 代码员工 | `04_代码员工.md` | 干活的主力 |
| 4 | Debug | `05_Debug.md` | 接收代码员工的产出 |
| 5 | 高级代码 | `03_高级代码.md` | 按需介入，可以晚起 |
| 6 | 美工 | `06_美工.md` | 按需介入 |
| 7 | 部署 | `07_部署.md` | 最后起，平时闲着 |
| 8 | 智囊（可选） | `08_智囊.md` | 不开也能跑，但需求就没审校了 |

**开完检查**：双击 `开机检查.bat`，应该看到 8 个工位都"空闲（正常）"或"未接过活"，
没有"⚠️ 卡住"。

## 复制完之后：怎么用

投一个需求进去，整条链路就会自己转起来：

```
把 [需求]_xxx.md 丢进 D:\ai-workflow\projects\P001_第一个项目\01_总控\收件箱\
```

然后你什么都不用做，只看：
```
D:\ai-workflow\projects\P001_第一个项目\00_人类总控\汇报终端\
```

这是**唯一的人类窗口**。总控会往里写进度、待决策、上线通知。

详细操作看 `01_操作手册\02_日常使用说明.md`。

## 三条铁律（违反任何一条，整套就会停摆）

### 1. 员工不说话

除总控向人类请示外，**任何员工在任何情况下都不得输出文字**。不写总结、不报状态、
不说"已完成"。它的回复只能是工具调用。

**原因**：AI 一输出文字，这一轮就结束了。循环断了，没有人会来叫醒它。

### 2. 文件必须归档

每个文件处理完，必须从收件箱移到自己工位的 `已处理\`。

**原因**：取件逻辑是"收件箱里第一个文件"。不移走，下一轮还取到同一个文件，
形成死循环。

### 3. 版本号只有总控能分配

其他任何角色只能用 ID（`20261031-1405-01`），不得自造 `v1.2.3`。

**原因**：版本号是部署和回滚的唯一锚点。多个角色自造版本号，回滚时会找不到对应成果。

## 三个最容易踩的坑

| 坑 | 现象 | 处置 |
|---|---|---|
| 忘了点 MCP「信任」 | 员工全部卡在 `NO_FILE`，收件箱有文件也不动 | 连接器管理 → 自定义连接器 → 信任 |
| `_GLOBAL_STATUS.md` 是 `PAUSED` 忘了改回来 | 所有窗口启动后立刻停 | `python tools\pause.py off`，再逐个叫醒 |
| 同一角色开了两个窗口 | 同一文件被处理两次，产出重复 | 关掉一个。锁只能防并发，防不了重复消费 |

中间全是 AI 自己在转。
